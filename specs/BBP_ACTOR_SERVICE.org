* 2. Document boundary

=bbp.document_boundary= is the only production boundary for StarIntel document parsing, field access, construction, serialization, and validation.

Production modules must not import migration-only flat modules such as:

- =starintel_doc.targets=
- =starintel_doc.hosts=
- =starintel_doc.relations=

The service has no implicit 0.8 adapter. Flat documents are rejected rather than rewritten.

** 2.1 Canonical envelope

Every produced document contains:

- =_id=
- =dataset=
- canonical =dtype=
- =schema_version: "0.9.0"=
- integer =version=
- RFC 3339 =date_added= and =date_updated=
- structured =sources=
- =evidence=
- canonical =data=
- preserved =extensions=

Unknown top-level and dtype-data fields are rejected according to the pinned schema.

** 2.2 Validation errors

The boundary exposes categorized failures. Required categories include:

- =invalid_json=
- =invalid_encoding=
- =unsupported_spec_version=
- =invalid_enum= for aliases
- =unknown_object_type=
- =missing_required_field=
- =wrong_type=
- =invalid_datetime=
- =undeclared_field=
- =schema_revision_mismatch=
- =unexpected_dtype=

Target consumers report the category without logging an entire payload.

** 2.3 Target access

A target is validated before dispatch. Actor code accesses =id=, =dataset=, =actor=, =target=, =delay=, =recurring=, =options=, =sources=, and =extensions= through the boundary wrapper rather than raw =data= layout.

BBPD additionally requires a non-empty =data.actor= even though the shared schema requires only =data.target=.

** 2.4 Builders

The boundary constructs canonical target, domain, host, URL, and relation documents.

Nmap service observations are embedded objects under =host.data.ports=:

#+begin_src json
{"port": 443, "name": "https", "version": "nginx 1.25"}
#+end_src

A service observation is not a standalone dtype.

Derived source provenance appends:

#+begin_src json
{"kind": "tool", "name": "subfinder"}
#+end_src

Existing structured sources and unrelated extension namespaces are preserved.

** 2.5 Compatibility and identity

This migration changes the envelope, not retry identity policy:

- domain ID: legacy deterministic hash of domain and record type
- host ID: legacy deterministic hash of IP
- URL ID: legacy deterministic hash of URL and content
- target ID: legacy deterministic hash of dataset, target, and actor
- relation ID: ULID until issue #5 replaces it with the approved deterministic relation identity

These hashes are deduplication keys, not integrity proofs.

* 3. RabbitMQ contract

The documents exchange is a durable topic exchange.

| Operation | Routing key |
|-----------+-------------|
| external target delivery | =actors.<actor>.new.target= |
| durable new finding | =documents.ingest.<dtype>= |
| persisted-document event | =documents.new.<dtype>= |
| update ingest | =documents.updated.<dtype>= |
| actor event | =event.<eventType>= |

A new finding must not be sent directly to =documents.new.*=.

The strict boundary does not alter publisher settlement or acknowledgement behavior. Issue #4 owns confirmed publication and ACK/NACK semantics.

* 4. Tool behavior

** 4.1 Subfinder

- input: strict target
- output: domain documents
- relation: root domain to discovered domain

** 4.2 Nmap

- input: strict target
- output: host documents with embedded port/service observations
- relation: target to host

Parser finalization remains issue #6.

** 4.3 Httpx

- input: strict target
- output: URL documents
- relation: target to URL

** 4.4 Katana

- input: strict target
- output: discovered URL documents
- relation: target to discovered URL

** 4.5 DNS resolver

- input: strict persisted domain from =documents.new.domain=
- output: validated domain update through =documents.updated.domain=
- update preserves =_id=, =_rev=, sources, evidence, extensions, and unrelated data

* 5. Packaging and conformance

Python requires 3.10 or newer. The Python dependency and Nix derivation use the same pinned =starintel-doc= revision.

The schema is supplied through =STARINTEL_CONFORMANCE_ROOT= or =STARINTEL_SCHEMA=. Startup rejects a package/spec/schema revision mismatch.

Required checks:

- repository unit tests
- upstream Python conformance fixture suite
- package build and dependency check
- =nix flake check=
- =nix build=
